Security

Verify before you trust. This page describes the design goals of the preview, not a certification.

What is verified and pinned

  • Bundles are signature-checked before install or upgrade.
  • Components are pinned to the versions a release was tested with.
  • The licence is signed and verified locally, with no call home.

How releases will be signed

Each release is planned to publish checksums, a detached signature and an SBOM. The signing method and public key will be documented on the download page with the first build.

Hardening evidence

Hardening profiles can export an evidence bundle describing what was configured, for your auditors.

Reporting a vulnerability

Write to security@zyvor.dev. Please include affected versions and steps to reproduce, and allow us reasonable time to respond before public disclosure.

Zyvor Kubeza is built on K3s and is not affiliated with SUSE or Rancher. Issues in upstream components should also be reported to their maintainers.
