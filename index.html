Why

Edge clusters should be boring.

You run clusters in shops, plants, hospitals and racks nobody visits. Kubeza is built so that installing, upgrading and recovering them is a short, checked, repeatable routine, not an afternoon of YAML.

Small

Built on K3s

A compact, single-binary-friendly Kubernetes base that suits modest hardware, with the pieces an edge site needs already decided.

Complete

Gateway included

The Setura Gateway API controller is built in instead of Traefik, so ingress is configured with the standard Gateway API from day one.

Safe

Reversible by design

Upgrades roll back automatically when health checks fail. Backups are verified by a real restore, not just a file on disk.

How it works

Three steps. Nothing surprising.

1

Check

zkube preflight inspects the host (CPU, memory, disk, time, ports) and tells you what to fix before anything is touched.

2

Plan

zkube plan shows exactly what an install would do for your chosen profile. It changes nothing.

3

Install

zkube install server applies the plan from a verified bundle. zkube doctor confirms the result.

Features

Everything one binary can carry.

All of it is in early preview and described as planned behaviour.

One zkube binary

Install, join nodes, upgrade, back up, restore and audit from a single command line.

Upgrades with automatic rollback

If the cluster is not healthy after an upgrade, Kubeza returns to the previous version for you.

Backup and verified restore

Restores are exercised and checked, so you learn a backup is good before the day you need it.

Hardening with evidence

Apply a hardening profile, then export an auditor evidence bundle that shows what was configured.

Offline signed bundles

Install and upgrade without internet access from bundles whose signatures are verified before use.

Optional Netra observability

Turn on Netra for eBPF-based network observability when you want to see traffic, and leave it off when you do not.

Setura Gateway built in

A Gateway API controller ships with the distribution instead of Traefik.

Security and offline first

Verify first. Then run. Offline if you must.

Every artefact is meant to be checked before it is trusted, and nothing needs the internet to work once it is on site.

Signed and checked

Releases are planned to ship with checksums, a signature and an SBOM, and the installer verifies bundles before it uses them.

Offline from the start

Signed offline bundles let you install and upgrade sites with no outbound access.

The never-brick promise

The licence never stops a running cluster.

Kubeza uses a signed offline licence, checked locally with no call home. If it expires or is missing, your running cluster keeps running. Only new installs and upgrades are affected.

FAQ

Questions, answered plainly.

Is Zyvor Kubeza available today?

No. It is an early preview and no binary has been released yet. You can request early access from the download page.

Is it K3s?

No. Zyvor Kubeza is built on K3s and adds its own tooling and components. K3s is a trademark of SUSE, and Zyvor Kubeza is not affiliated with SUSE or Rancher.

Why Setura instead of Traefik?

Setura is a Gateway API controller from Zyvor that is built into the distribution, so ingress uses the standard Gateway API from the start.

What happens if my licence expires?

Your running cluster keeps running. The licence is signed and verified offline and never stops a running cluster.

Does it work without internet?

That is the plan: offline signed bundles for install and upgrade. This is part of the preview.
